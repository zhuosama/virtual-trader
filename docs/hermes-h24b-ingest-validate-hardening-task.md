## Goal

Address Claude review findings on the ingestion/validation side:

- HIGH H3: insufficient snapshot coverage must be a blocker, not a warning.
- HIGH H4: Tushare partial data must not be silently accepted as clean historical universe.
- MEDIUM M1: invalid dates must not be silently propagated by `_day_before()`.
- MEDIUM M4: `validation_report.json.status="PASSED"` must not coexist with deploy blockers in a misleading way.
- LOW L4: `snapshots_to_intervals()` should preserve provider/index/source fields from input snapshots.
- NIT N1: clarify current-universe fallback comments.

## Required Implementation

### 1. Strict date handling

Add helper(s) for ISO date parsing/validation.

`_day_before(date_str)` must not silently return invalid input. It should raise `ValueError` or otherwise cause validation/test failure.

`snapshots_to_intervals()` should validate `trade_date` values before generating intervals.

### 2. Tushare coverage enforcement

In `fetch_historical_universe(start, end)`:

- After fetching `index_weight`, compute min/max snapshot `trade_date`.
- If `snapshot_min > start` or `snapshot_max < end`, do not write clean historical universe rows.
- Return `None` or write explicitly blocked rows with `SURVIVORSHIP_BIAS`; prefer not overwriting existing data on insufficient coverage.
- Print a clear diagnostic that historical coverage is insufficient.

Do not let one month of returned Tushare data overwrite `universe.jsonl` as clean `tushare:index_weight`.

### 3. Validation blockers/status semantics

Extend `validate()`:

- If snapshot coverage is insufficient versus the available price date range, add `survivorship_bias` to `data_quality_blockers`.
- Do not leave `status="PASSED"` when `data_quality_blockers` is nonempty.
- Recommended statuses:
  - `FAILED`: structural/parse errors,
  - `BLOCKED`: files structurally valid but deployment/data-quality blockers exist,
  - `PASSED`: files valid and no blockers.
- Add `can_deploy_data_quality: bool` to `validation_report.json`.

Keep the distinction clear: `BLOCKED` is not a file-structure failure, but it is not deployable.

### 4. Preserve source fields in interval conversion

In `snapshots_to_intervals()`:

- Do not hardcode `source_url` and `index_code` when snapshot rows contain those fields.
- Use `source_url`, `index_code`, and `source_provider` from the interval-start snapshot.
- For HS300/Tushare defaults are still fine when fields are missing.

### 5. Current-universe fallback comment

Clarify that current AKShare constituent fallback uses a uniform fallback start date, not an approximation of actual index entry date.

### 6. Tests

Add focused tests in `tests/test_ingest_cn_pit_data.py`:

- `_day_before("bad-date")` raises,
- `snapshots_to_intervals()` rejects invalid `trade_date`,
- interval conversion preserves `source_url`, `index_code`, `source_provider`,
- Tushare partial coverage does not overwrite existing universe data,
- `validate()` reports `BLOCKED` when data quality blockers exist,
- `validate()` uses `PASSED` only when no blockers exist (can use a small temp/data monkeypatch),
- snapshot coverage earlier/later than price range becomes blocker, not warning.

Use monkeypatching/temp dirs rather than live network.
